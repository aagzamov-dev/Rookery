Read this file fully before changing anything. Then read the spec for the feature you're working on (the current one is [07-SQL-CONNECTIONS.md](07-SQL-CONNECTIONS.md), §10 lists what is built and what is left).

## 1. What Rookery is
- **What:** a local-first desktop SSH server manager for Windows and macOS (Android later), meant as a lighter MobaXterm / Termius.
- **Server tabs:** one tab per server. Inside it: Overview, Terminal, Files (SFTP), Docker, Services, Processes, Logs, Settings views.
- **Pages:** Dashboard, Snippets, Hosts & identities, Shortcuts, Backup & sync, Settings.
- **Storage:** everything lives on the user's computer. Secrets are in an encrypted vault, unlocked with a 4-digit PIN. There is no account.
- **Repository:** https://github.com/aagzamov-dev/Rookery (public, MIT). Default branch `main`.
- **Status:** v0.1 – v0.7 built (see [02-ROADMAP.md](02-ROADMAP.md), [CHANGELOG.md](CHANGELOG.md)). v0.7 = the SQL connections core. Next: **v0.7.1 SQL shortcuts** (Docker "Open in SQL", Laravel `.env`, find local databases, query history).

## 3. Commands (Windows dev machine: PowerShell or Git Bash)
- Rust is in `%USERPROFILE%\.cargo\bin`. In PowerShell, prefix with `$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path";`.
- **Run the app:** `npm run dev` (repo root; Tauri dev with hot reload).
- **Tests and checks:**
  - `cargo test -p rookery-core`: Rust tests. This **also regenerates `apps/desktop/src/ipc/bindings/*.ts`**; run it after changing any `#[derive(TS)]` type.
  - `cargo build -p rookery-tauri`: build the desktop crate.
  - `npx tsc --noEmit -p apps/desktop`: typecheck.
  - `npx vitest run` (in `apps/desktop`): frontend tests.
- **Installer:** `npx tauri build --bundles nsis` (repo root). It needs the env vars `TAURI_SIGNING_PRIVATE_KEY` / `_PASSWORD` set from `%USERPROFILE%\.tauri\rookery-updater.key(.password)`, because `createUpdaterArtifacts` is on.
- **Screenshots:** `npx vite --port 1420` in `apps/desktop`, then `http://localhost:1420/demo.html?scene=<scene>`. Capture with headless Edge `--screenshot`.

## 4. Architecture rules (do not break)
1. **Lazy load:**
   - A host in the DB never connects by itself; only `ConnectionManager::acquire()` (a `Lease`) opens a session.
   - Collectors run only while their view is visible (`subscriptions/engine.ts` desired-state reconciler).
   - Pages (Dashboard etc.) render from SQLite and never connect on open.
   - No background polling of servers. Dashboard auto-sync is opt-in per group.
2. **Secrets stay in Rust:**
   - Passwords, keys and tokens never go to the webview. Commands may *accept* a secret and store it in the vault; nothing ever *returns* one.
   - Vault secret ids: `identity:<id>:<kind>`, `backup:password`, and (v0.7) `dbconn:<id>:password`.
3. **One event channel:**
   - Rust → UI goes through `CoreEvent` (`events.rs`), forwarded on `"core"`.
   - Add variants there, then route them in `ipc/events.ts`.
4. **`rookery-core` has no Tauri deps.** Blocking work (Argon2, file IO) must not run on async workers: use `spawn_blocking` (see `blocking()` in commands.rs) or `block_in_place`.
5. **Migrations are append-only** (`MIGRATIONS` in db.rs). Never edit an old one.
6. **Settings:**
   - The webview may only write `ui.*` keys (`setting_set` checks this).
   - Per-device keys are listed in `LOCAL_SETTING_KEYS` / `backup.*` and are **not synced**.
7. **Sync & backup** (docs/04 §5): any new synced entity needs:
   - an `updated_at` version, and deletion through `delete_tracked` (tombstone kind);
   - inclusion in `backup::collect`, `merge`, `data_revision`, `wipe_synced` and `apply_delete`;
   - a test in `backup.rs`.
8. **Legacy names, keep them** (the app was called "Rook" before 2026-10-15):
   - the `rook` → `rookery` migration code in lib.rs (data dir) and vault.rs (keychain);
   - the server-side shell-integration marker `rook-shell-integration-v2`, `__rook_osc7`, `rook-ok`;
   - import of old `rook-keymap` / `rook-snippets` files.
9. **Keyboard:**
   - Every function goes in `keys/actions.ts` (`ActionId` + `ACTIONS`), handled in `keys/dispatcher.ts`.
   - Chords use `KeyboardEvent.code`; `Mod` = Ctrl (Win) / ⌘ (Mac).
   - On Windows the shell owns plain Ctrl+letter unless the user bound it.
10. **zustand v5:** a selector must not return a new array or object on every call (it loops forever). Use `useMemo`, or select primitives.
11. **Dependencies:**
    - The workspace has `rust-version = "1.90"`.
    - Before adding a crate, check `cargo info <crate>@<ver>` for `rust-version`, features, and yanked transitive deps. Example: all `zip` 2.x / 4.x are yanked, so `tauri-plugin-updater` runs with `default-features = false`.

## 5. Working rules (how the product owner wants us to work)
- **Language:** the owner writes quick English. Answer in simple, clear English, with short lists.
- **"no code change" / "explain only" / "no change now"** means: answer only, edit nothing.
- **Design or colour changes:** show options first; don't change the design unasked.
- **Ask before** destructive actions, publishing (push, tag, release) and paid services. **Commit only when asked.** Commit messages end with:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- **After each feature:**
  - run all checks (§3);
  - update docs (02-ROADMAP status, 03 / 04 sections, CHANGELOG `## x.y.z`, README tour if user-visible);
  - say exactly what was and wasn't verified.
- **Windows tooling quirks:**
  - `python` is not installed: use `node -e` / small `.mjs` scripts in the scratchpad for multi-line edits.
  - PowerShell `Set-Content -Encoding utf8` adds a BOM; strip it from Cargo.toml.
  - PowerShell strips inner quotes in `cargo add --target 'cfg(...)'`: edit Cargo.toml by hand.
- **Releases:**
  1. Bump the version in `Cargo.toml` (workspace), `crates/rookery-tauri/tauri.conf.json`, `package.json`, `apps/desktop/package.json`.
  2. Add a `docs/CHANGELOG.md` `## x.y.z` section.
  3. Commit, then `git tag vX.Y.Z && git push && git push --tags`.

  Details: [06-AUTO-UPDATE.md](06-AUTO-UPDATE.md) §4. Pushing `main` only runs CI; it never releases.

- **Components and dialogs:**
  - Reuse `ui/primitives.tsx` and `ui/ContextMenu.tsx`.
  - Use `askConfirm` / `askText` (`stores/dialogs.ts`) for dialogs; there's a `secret: true` option for masked input.
